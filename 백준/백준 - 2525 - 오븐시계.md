분류 : 조건문

처음 내 접근 방식은 다음과 같았다.

A와 B는 각각 시간, 분에 해당하니까 Hour의 H, Minute의 M이라는 변수로 지정했다.
그리고 오븐구이를 하는 데 필요한 시간을 Value의 V로 지정했다.

resultH, resultM 이라는 변수도 선언했는데, 이 변수는 계산이 끝나고 최종적으로 sout으로 출력될 값을 담는 역할이었다.

그리고 calculator라는 메서드를 만들었는데, 이 메서드는 addH, addM 이라는 변수에 담길 값을 계산한다. addH(addM)의 역할은 사용자의 입력값 H(M)와 addH(addM)를 더하여 최종적으로는 resultH(resultM)의 값을 구하는 것이다.

그리고 나는 V의 최대값이 1000인 점에 주목했다.
1000분은 16시간 40분이다. 만약 현재 시각이 07시 19분이라면 16시간 40분 후는 23시 59분이다. 즉 나는 현재 시각이 07시 19분 이하라면, 간단히 V를 시간:분 으로 환산해서 더하면 되겠다는 결론에 도달했다. 하지만 이 생각은 너무 편협한 생각이었다.
V의 최대값 1000은 최대값일 뿐이지 항상 1000이 되는 것이 아니다.
그러므로 현재 시각이 07시 19분을 초과했다고 해도 딱히 다른 계산법을 도입해야 하는 것은 아니었다. 게다가 calculator라는 메서드를 도입하고 계산은 더욱 복잡해졌고 코드의 길이는 길어졌다. 결국 나는 이 아이디어를 폐기하고 다시 처음부터 생각하기로 했다.


나는 예제 입력의 테스트 케이스를 토대로 내가 내 머리속에서 저 계산을 어떤 과정을 거쳐 계산하는지에 주목했다.

먼저 입력이 14, 30, 20 으로 주어졌을 때이다.

이 답은 너무나 간단하게 계산되지만 그 과정은 다음과 같았다.

먼저 30과 20을 더한다. 더하면 50이다. 50이 최종적인 M의 값이다.
즉 M == M + V 다.

그런데 만약 입력이 23 48 25 라면? 48 + 25는 73으로, 73분을 시:분으로 환산하면 1시간 13분이다. 우리는 이 1시간 13분을 단순히 23:48에 더해서 답을 내지만, 이 과정을 자세히 풀어보면 다음과 같다.

73에서 1시간 13분을 도출해내는 방법은 73 / 60 = 1, 나머지는 13이다. 나머지를 구하는 방법은 73 % 60 = 13. 즉 1과 13을 추출해 내는 방법은 다음과 같다.
1시간 == 73 / 60
13분 == 73 % 60

그렇다면 이전의 케이스를 포함하려면 어떻게 일반화 해야 할까? 만약 20+30=50 일 때, 50 % 60은 10이 나온다. 10을 사용할 수 가 없다. 그러므로 여기서 if 분기를 사용할 수 있다.

if (M+V >= 60)
①
else
②

즉, ①에서는 (M+V) % 60 이 최종적인 M의 값이 된다.
②에서는 M+V 값이 최종적인 M의 값이 된다.

H값은 ①에서 다음과 같이 구해진다.
①에서 M+V값은 항상 60보다 크거나 같다. 즉 무조건 1시간 이상이다.
그러므로 기존의 사용자 입력값 H 값에 (M+V) / 60 한 값을 더해야 한다.

H = 23 이고 M = 48, V = 25 일 때, M+V == 73.
73 / 60 은 1이고, 이 1을 H와 더하면 최종적인 H값이다.

H + 1 = 24.

즉 최종적인 H값은 24, M값은 13이다.

이제 H값이 24 이상일 경우를 처리해야 한다.
만약 여기까지의 계산에서 H값이 24미만이면 최종 값이 되었겠지만, 디지털 시계는 23시 59분에서 1분이 지나면 0시 0분이 되므로, 24는 0으로 표시해야 한다.

이것에 대해서는 다음과 같은 규칙을 활용하여 해결했다.
24보다 작은 수, 즉 1~23에서 24를 빼면 항상 음수이다.
1 - 24 = -23
10 - 24 = -14
23 - 24 = -1.

그런데 24 이상의 수를 빼면
24- 24 = 0
25 - 24 = 1
27 - 24 = 3
36 - 24 = 12.

즉 최종 H값에서 24를 뺐을 때, 음수가 나온다면 최종 H값을 그대로 사용하면 된다.
음수가 아니라면, 최종 H값에서 24를 뺀 값을 최종 H값으로 사용해야 한다.

나는 이것을 if문 안에 중첩 if문을 삽입하여 H-24 값이 0과 크거나 같을 때에만 H-24값을 최종 H값으로 사용하도록 코드를 작성했다.

그 코드는 다음과 같다.
```java
import java.util.Scanner;

public class Main {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        int H = sc.nextInt();
        int M = sc.nextInt();
        int V = sc.nextInt();

        if ((M+V)>=60){
            H = H+((M+V)/60);
            M = (M+V)%60;
            if((H-24)>=0){
                H = H-24;
            }
        }
        else {
            M = (M+V);
        }

        System.out.println(H+" "+M);

    }
}
```

즉 이 문제는 다음과 같이 처리할 수 있다.
1.  M+V 값이 60 이상이 되는 경우를 처리
	1. 60 미만이라면 최종 H값은 H, 최종 M값은 M+V
2. M+V 값이 60 이상일 경우에 계산된 H값이, 24 이상인 경우를 처리.
	1. H-24 값이 0또는 양수라면 최종 H값은 H-24, 아니라면 최종 H값은 H+((M+V)/60)

1번은 입력값이 17 40 80 일 때, 40+80 = 120이 되는 경우를 처리하는 것이다.
2번은 120이 2시간 0분이 되어 H값에 2가 더해졌을 때, 그 값이 24 이상이 되는 경우를 처리한다.

이 문제의 시간 복잡도는 O(1)이다.
입력 크기 n은 3인데, 3은 늘어나지 않는다.

n = 3일 때, 이 로직의 연산의 수는 늘어나지 않고 고정된다.
반복문은 없다. 

따라서 O(1)임.
