기존 26개의 알파벳 중에
크로아티아 알파벳은 형태가 좀 다른 것이라고 이해했다

c는 2가지 버전이 있고
č
ć

d도 2가지 버전
dž
đ

l은 lj

s -> š
z -> ž

하지만 입력되는 단어는 원래의 크로아티아 알파벳의 형태로 주어지지 않고, 변경된 크로아티아 알파벳으로 주어진다.

즉 내가 짜야할 로직은 일반 알파벳과 크로아티아 알파벳을 구분하고 갯수를 정확히 세야 한다.

그러니까 
`dž` 는 `dz=` 로 표현하는데,
내 로직은 이것을 `크로아티아 문자 1개`로 인식하고 갯수를 세야 한다.
dz에 `d` 와 `z`가 포함되니까 문자 2개로 인식해서는 안 된다.

우선 구분 법을 작성해보자

각 문자를 변경한 문자를 살펴보니 다음과 같은 공통점이 있다.
변경된 문자를 거꾸로 보면 
`=`로 시작하거나, 
`-`로 시작하거나, 
`j`로 시작한다.

그럼 나는 입력으로 주어지는 문자를 받고 거꾸로 탐색하는데, 현재 검사 대상인 문자 하나가 저 셋 중 하나일 때, 그 문자가 진짜 크로아티아 문자인지 판별하는 로직을 짜면 된다.


그럼 세 경우에서 어떻게 처리할지 로직을 설계해보겠다

1. `=`일 경우
이 경우엔 현재 선택된 단어 다음으로 올 단어가 다음 중 하나라면 크로아티아 문자이다.
- `c`
- `z`*
	- z의 경우 z=와 dz=가 있다. 이를 판별하기 위해, 그 다음 문자까지 검사한다. d가 아니면 `z=`인 것이다.
- `s`

2. `-`일 경우
- `c`
- `d`

3. j일 경우
- `l`
- `n`

# **검사**가 이루어지는 방식

입력된 문자열을 거꾸로 한 문자씩 검사한다.
검사 횟수는 입력된 문자열의 길이.

ljes=njak

현재 검사 대상 : k -> 6개 중 하나의 크로아티아 문자가 아니지만 갯수 1 증가

a : 아니므로 1 증가

j : 검사 필요
- 다음 인덱스가 n이거나 `l`인 경우 : 
	- 크로아티아 문자임. 갯수 1증가하고 검사 횟수를 1 증가 한다[^1].
- 아닌 경우 :
	- 현재 문자는 6개 중 하나의 크로아티아 문자에 해당되지 않는다. 

만약 현재 문자가 `=`라면,

= : 
- 다음 인덱스가 c 나 s일 경우
	- 크로아티아 문자이므로 갯수1 증가하고 검사 횟수 1증가한다.
- 다음 인덱스가 z일 경우
	- 이 경우 `z=` 이므로 크로아티아 문자인 것으로 확인되어 검사가 끝날 수도 있지만 이 문자가 `dz=`일 수도 있기 때문에 이 시점에서 검사를 한 번 더 수행해야 한다.
		- 그 다음 인덱스가 `d`일 경우
			- 이 문자는 `dz=`이므로 크로아티아 문자이다. 갯수 1 증가하고 검사 횟수를 2 증가.
		- d가 아닌 경우
			- 이 문자는 `z=`이다. 갯수 1 증가하고 검사횟수를 1 증가.

현재 검사하는 문자가 `-`인 경우는 j일 때와 동일하므로 추가로 적지는 않겠다.

# 1차 시도 - 실패
참조하는 배열의 범위를 초과했음

```java
import java.io.*;  
import java.util.*;  
  
public class Main {  
    public static void main(String[] args) throws IOException {  
        BufferedReader br = new BufferedReader(new InputStreamReader(System.in));  
        BufferedWriter bw = new BufferedWriter(new OutputStreamWriter(System.out));  
        StringBuilder sb = new StringBuilder();  
  
        // 문자 입력  
        String word = br.readLine();  
  
        //검사  
        int answer = 0;  
        for (int i = 0; i < word.length(); i++) {  
            char target = word.charAt(word.length()-1-i);  
            char nextTarget = word.charAt(word.length()-2-i);  
            if (target == '=') {  
                // c=, s=일 경우 판단  
                if (nextTarget == 'c' || nextTarget == 's') {  
                    answer++;  
                    i++;  
                }  
                // dz=일 경우, z=일 경우 판단  
                else if (nextTarget == 'z') {  
                    //dz=일 경우 판단  
                    if (word.charAt(word.length()-3-i) == 'd') {  
                        answer++;  
                        i +=2;  
                    }  
                    else {  
                        //이 문자는 z=임.  
                        answer++;  
                        i++;  
                    }  
                }  
            }  
            // c-, d-일 경우 판단  
            else if (target == '-') {  
                  
                if (nextTarget == 'c' || nextTarget == 's') {  
                    answer++;  
                    i++;  
                }  
            }  
            else if (target == 'j') {  
                  
                if (nextTarget == 'l' || nextTarget == 'n') {  
                    answer++;  
                    i++;  
                }  
            }  
            else {  
                //=,-j가 아니라서 일반 문자임  
                answer++;  
            }  
        }  
  
        sb.append(answer);  
  
        //출력  
        bw.write(sb.toString());  
        bw.flush();  
        bw.close();  
        br.close();  
    }  
  
}
```

## 무엇이 문제?
문제는 검사 부분의 
`char nextTarget = word.charAt(word.length()-2-i);  `
코드에서 발생했다.
만약 현재 검사 중인 단어가 `abc`인데 현재 검사중인 문자는 `a`라고 하자.
target에는 'a'가 저장될 것이다. 하지만 nextTarget에는? 배열의 참조 범위를 벗어나게 되어 오류가 발생한다.

## 어떻게 해결했는가?
nextTarget이 필요한 경우는 '현재 검사 대상인 단어'(target)이 `=`, `-`, `j` 중 하나인 경우 뿐이다.
그러므로 nextTarget을 저장하는 행위는 "target이 =,-,j 중 하나인 경우, 다음 문자가 어느 것인가?"를 조사할 때만 수행하면 된다.

발견한 반례:

1.
입력된 문자열이 `jxxxx`일 경우
target이 j일 때 nextTarget을 저장하려는 행위를 하게 되면서 오류가 발생한다.

**해결** 
target이 입력된 문자열의 첫 번째 문자와 일치한다면 정답 갯수를 1증가, continue.

2.
입력된 문자열이 `z=`인 경우, target이 =라고 하자.
이 경우 nextTarget을 저장하는 행위가 실행되고 이는 정상적으로 실행된다. 그러나
nextTarget이 z인 경우 nextTarget의 다음 target을 저장할 때, 배열의 조사 범위를 벗어나게 된다.
`[0][1][2]`
`[z][=][]`
target : Index 1
nextTarget : Index 0
next의 nextTarget : Index -1...? 배열 참조 범위 초과

**해결**
nextTarget이 입력된 문자열의 첫 번째 문자열과 일치한다면 z=이므로 정답 갯수를 1증가.


# 8차 시도 - 성공

3차~7차에서 틀렸던 부분을 나열하려고 한다

```java
import java.io.*;

public class Main {
    public static void main(String[] args) throws IOException {
        BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
        BufferedWriter bw = new BufferedWriter(new OutputStreamWriter(System.out));
        StringBuilder sb = new StringBuilder();

        // 문자 입력
        String word = br.readLine();
        int lastCharIdx = word.length()-1;

        //검사
        int answer = 0;
        for (int i = 0; i < word.length(); i++) {
            char target = word.charAt(lastCharIdx -i);
            if (target == '=') {
                // c=, s=일 경우 판단
                // nextTarget을 저장하려면 현재 검사하는 문자열의 인덱스가 1이상이어야 함.
                if (lastCharIdx -i >= 1) {
                    char nextTarget = word.charAt(lastCharIdx - 1 - i);
                    if (nextTarget == 'c' || nextTarget == 's') {
                        answer++;
                        i++;
                    }
                    // dz=일 경우, z=일 경우 판단
                    else if (nextTarget == 'z') {
                        //nextTarget == z이면서 첫 번째 문자라면 즉시 검사 종료
                        if (lastCharIdx-1-i == 0) {
                            answer++;
                            i++;
                        }
                        //dz=일 경우 판단
                        else if (word.charAt(word.length() - 3 - i) == 'd') {
                            answer++;
                            i += 2;
                        } else {
                            //이 문자는 z=임.
                            answer++;
                            i++;
                        }
                    } else {
                        //그냥 =임
                        answer++;
                    }
                }
                else{
                    // 아니라면 '='
                    answer++;
                }
            }
            // c-, d-일 경우 판단
            else if (target == '-') {
                if (lastCharIdx -i >= 1) {
                    char nextTarget = word.charAt(word.length() - 2 - i);
                    if (nextTarget == 'c' || nextTarget == 'd') {
                        answer++;
                        i++;
                    }
                    else {
                        //다른 문자면 이 문자는 -인 것으로 치고 다음 검사
                        answer++;
                    }
                }
                else {
                    // - 임
                    answer++;
                }
            }
            else if (target == 'j') {
                if (lastCharIdx -i >= 1) {
                    char nextTarget = word.charAt(word.length() - 2 - i);
                    if (nextTarget == 'l' || nextTarget == 'n') {
                        answer++;
                        i++;
                    } else {
                        //그냥 문자 j이다.
                        answer++;
                    }
                }
                else {
                    //그냥 문자 j이다.
                    answer++;
                }
            }
            else {
                //=,-j가 아니라서 일반 문자임
                answer++;
            }
        }

        sb.append(answer);

        //출력
        bw.write(sb.toString());
        bw.flush();
        bw.close();
        br.close();
    }

}
```

1.
`-`, `=`,가 그냥 문자로 쓰였을 때 문자로 인정하지 않았으므로(내가) 점수로 추가하는 로직이 빠져있었음.

2.
target이 `-`일 때를 판단할 때, 
`if (nextTarget == 'c' || nextTarget == 's')` 가 아니라
`if (nextTarget == 'c' || nextTarget == 'd')` 여야 한다. 어이없는 실수

3.
입력된 단어가 `z=dz=` 인 경우,

`[0][1][2][3][4]`
`[z][=][d][z][=]`

target이 4일 때
nextTarget은 3인데, 이 때 2도 검사하여 최종적으로 `dz=`임을 판별해야 하지만
7차 시도의 코드에서는 `target == word.charAt(1) && nextTarget == word.charAt(0)` 이 true일 경우 현재 target에 해당하는 인덱스는 1인 것으로 간주하여 즉시 검사가 종료된다. 이 경우 실제 검사 중인 인덱스는 4임에도 불구하고 검사는 종료된다. 따라서 이 문제를 글자 자체를 비교하는 것이 아니라 현재 위치를 확인하는 방법으로 바꿔서 수정 완료 했다.

4.
기타 오류는 else문의 부재로 인해 발생하였다.

1,2,3,4를 고친 버전이 8차 시도 코드이다.


# 문제 수정 요청

요지: -,=도 크로아티아 알파벳으로 볼 수 있는가?

나 : 아니다.

왜?
-나 =는 dz= 등의 크로아티아 알파벳을 만들기 위한 보조 기호일 뿐이기 때문이다.
그렇기 때문에 만약 d=같은 문자가 주어지면 이 것은 크로아티아 문자로 볼 수 없기 때문에 각각 분리하여 해석해야 하며, d는 문제에서 크로아티아 알파벳으로 치기 때문에 인정해야 하지만

(왜냐하면 "ljes=njak은 크로아티아 알파벳 6개(lj, e, š, nj, a, k)로 이루어져 있다."에서 a도 엄밀히는 로마자 알파벳일 뿐이지만 주어지는 단어가 크로아티아 알파벳으로 이루어져 있다고 했으므로 a도 크로아티아 알파벳이라고 봐야 할 것이다.) 

=는 알파벳도, 크로아티아 알파벳도 아니다. 

그래서 각 문자들을 크로아티아 문자로 치환했을 때, 크로아티아 알파벳으로서 의미를 가져야 한다고 생각한다.
(예 : "ljes=njak" 의 경우 각 단어를 크로아티아 문자로 치환했을 때, 그 문자 각각이 크로아티아 문자 하나하나로서 의미를 가져야 하지만 "`=====`"나 "----"의 경우, "t=i-q-g="의 경우, 각 문자는 그냥 기호의 연속이거나 알파벳과 기호가 섞인 문자열이므로 크로아티아 알파벳이라고 할 수 없다.)

그렇기 때문에 입력으로 주어지는 문자열은 '-', '='로만 이루어져 있거나, "d=", "a-"같은 문자열이 포함되서는 안 된다고 생각한다.

입력 값 설명 란에 "알파벳 소문자와 '-', '='로만 이루어져 있다." 라고 적혀있었기 때문에 문법에 맞지 않는 조합도 입력으로 주어질 수 있다고 하기엔 뭐 알고리즘적 허용으로 넘어갈 수 있다곤 하지만, 상식적으로 -, = 라는 기호를 알파벳으로 치지 않기 때문에 혼동을 주는 건 사실이다.
알고리즘 적 허용으로 넘어갈 거라면 지문에 "단, 크로아티아 알파벳으로 치환되지 않는 '-', '=' 등의 기호도 각각 하나의 글자로 셉니다." 라는 문구를 추가하던가 예제 입력으로 '---'같은 것을 넣었으면 한다.

[^1]: 검사 횟수를 증가하는 이유는 nj, lj는 문자 1개로 세기 때문에 갯수만 1 증가시키면 다음 반복에서는 n이나 l에 대해 또 검사를 수행하게 된다. 이 경우 n이나 l로 끝나는 크로아티아 문자는 없기 때문에, nj, lj는 2개의 문자로 계산되어버린다. 따라서 "검사 횟수 1 증가" == "크로아티아 문자인 것을 확인한 직후 다음 문자 하나는 이미 센 것으로 간주하는 행위" 이므로 검사 횟수 1을 증가 시키면 다음 반복에서 다음 문자를 검사하는 행위를 건너뛸 수 있다.
