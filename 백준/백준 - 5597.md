
https://www.acmicpc.net/problem/5597


테스트 케이스 1개 당 총 28개의 입력이 주어진다.
입력은 한 개 당 1줄이며, 총 28줄의 입력이 한 개의 테스트 케이스에서 주어진다.

입력되는 숫자는 1~30 이내의 숫자이다.

나는 입력되는 숫자 28개 중 나머지 2개를 찾아 오름차순으로 출력하면 된다.

출력은 한 개당 한 줄씩, 총 2줄을 출력하면 된다.


그렇다면 제출 안 한 학생을 어떻게 잡아내야 할까

이미 30개의 공간으로 가득 차 있는 int형 배열이 있다고 하자
그 안에서 랜덤한 공간 하나를 선택하고 제거하는데, 하나를 제거하면 배열의 크기 자체도 하나 줄어드는 방식으로 하면?
하지만 그렇게 한다면 오버헤드가 크지 않을까?

아니면, 배열을 순회하여 입력에 해당하는 숫자에 해당하는 배열의 공간에 1을 할당, 순회의 끝에는 30개의 공간 중 2개가 빌 것이므로 그 공간의 위치만 알아내면, 즉, 배열의 요소가 0인 인덱스의 번호가 곧 제출 안 한 학생의 출석번호일 것이므로 이 방법도 괜찮을 것 같다. 이 방법을 선택하여 로직을 작성했다.

1차 시도:
```java
import java.io.*;  
import java.util.*;  
  
public class Main {  
    public static void main(String[] args) throws IOException {  
        BufferedReader br = new BufferedReader(new InputStreamReader(System.in));  
        BufferedWriter bw = new BufferedWriter(new OutputStreamWriter(System.out));  
        StringBuilder sb = new StringBuilder();  
  
        //출석부  
        int[] lists = new int[30];  
  
        //출석 진행  
        for (int i = 0; i < lists.length; i++) {  
            int stu = Integer.parseInt(br.readLine());  
            //출석 처리  
            lists[stu] = 1;  
        }  
  
        //출석 검사  
        for (int i = 0; i < lists.length; i++) {  
            if (lists[i] == 0) {  
                sb.append(i+1).append("\n");  
            }  
        }  
  
        //출력  
        bw.write(sb.toString());  
  
        bw.flush();  
        bw.close();  
        br.close();  
    }  
}
```

결과: 런타임 에러 - ArrayIndexOutOfBounds

이유:
출석 처리 코드에서 배열의 범위를 넘어가버린다.
배열의 공간 30개이면 인덱스는 0~29이다. 그런데 배열의 인덱스 숫자가 stu로 주어진다면 범위를 넘어갈 수 밖에 없다. 주어지는 입력은 1~30까지의 숫자이기 때문이다. 따라서 나는 인덱스를 stu-1로 주어야 한다.

2차 시도 결과 : 런타임 에러 - Numberformat

이유:
for문의 반복 횟수에 문제가 있다.
분명 입력은 28회만 받는다. 그러나 for문은 30회 반복한다.
그러므로 빈 입력 2회를 더 받게된다.

배열의 크기를, 반복해야 하는 횟수로 착각한 내 실수임. 보통의 경우에는 그게 맞지만 이 문제를 해결하는 내 방법에서는 그렇지 않기 때문이다.

원인:

원인은 내가 로직을 명확하게 정리하지 않은 탓이기도 하다.
입력은 28개 고정이므로 첫 번째 반복문은 28회만 도는 게 맞다.

그러나 출석을 검사할 땐, 30명의 학생 전부를 검사해야 출석 안 한 학생을 찾을 수 있다. 그러므로 두번 째 반복문에서는 for문이 30회 반복되어야 한다.

3차 시도:
